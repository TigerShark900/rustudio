## 3. Inheritance (measured unless marked)

Script and LocalScript task.spawn/defer/delay, coroutine.create/resume, coroutine.wrap, xpcall error handlers, __index metamethods and BindableEvent callbacks all print identity 2 and fail pcall(settings) with missing Plugin. Command task.spawn/coroutine.wrap print 1; deferred command output was not fully captured.

A command thread connected a BindableEvent callback; a LocalScript fired it. Callback printed identity 1 and settings succeeded. Reverse direction: LocalScript connected, command fired; callback printed identity 2 and settings failed. Therefore callback authority follows the connector in these observations. This does not test passing a closure originally created at another identity to Connect.

Module code executes at requiring context's identity: same replicated module printed 1 for command require, then 2 for game require, with separate execution across those contexts. The module cache must not let a privileged require grant game execution privileged authority. Exact cache partitioning (identity versus script context/environment) remains unmeasured.

Loadstring: global exists in both contexts, but default server and client calls raise `loadstring() is not available`. Enabled-mode inheritance remains unknown. Proposed inherited authority is an implementation recommendation, not a measurement.

## 4. Globals and Studio game behavior

Both game contexts have callable settings, stats, UserSettings, PluginManager, printidentity, loadstring, getfenv, setfenv, newproxy and collectgarbage. Presence does not imply permission. settings and PluginManager raise missing Plugin. stats returns `Stats`, UserSettings returns `GlobalBasicSettings`; printidentity succeeds and returns nil. loadstring presence was checked separately from availability. collectgarbage() with no arguments errors in Studio but rustudio returns nil. getidentity, setidentity, getthreadidentity, setthreadidentity, gethiddenproperty, gethui and plugin are nil in both command and tested LocalScript environments.

RunService:IsStudio() returns true in both game contexts; Studio status does not elevate them to command authority. The restricted member results below record further Studio-only behavior and ordinary validation. No standalone Roblox Player comparison was performed, so successful access cannot by itself be attributed specifically to Studio.

## Implementation specification (proposed, not implemented)

1. Store security context per actual Luau thread, independently of source names, function environments and memory categories. Use Luau thread userdata/extra data with lifecycle cleanup or a weak-key registry keyed by mlua Thread. A pointer map requires GC/reuse cleanup; avoid the existing memory-category map's assumptions. Keep identity number, granted legacy capability bits and sandbox capability set distinct. Default Script/LocalScript to identity 2; assign explicit host contexts to harness/plugin/command entry points. Harness trust must be initialized by host entry, never inferred from a chunk named harness.
2. Extend api::Member to retain separate Read and Write security, Capabilities, NotScriptable, and inherited member declaration. api.rs currently retains only Read for property security; gen_stubs.py filters out restricted members. Preserve metadata for all members even where no implementation exists. Keep Security mapping table plus measured per-member overrides (UniqueId); do not promise an exact implementation based only on Security.
3. Check read before property value access, write before conversion/read-only validation where Studio exhibits that ordering, call at method invocation, connect and wait at signal operations, and global access at invocation. Restricted method/event handles must not permanently cache creator authority: use calling thread on each operation. Resolve nonexistent/NotScriptable members according to measured invalid-member precedence. Audit callback assignment separately. Explicit service/class create/access policies need checks beyond member security.
4. Centralize checks before real domain implementations and fallback stubs so implemented members cannot bypass policy. Relevant boundaries: runtime.rs Instance index/newindex/method dispatch, stubs.rs fallback, runtime_signals.rs connection/wait paths, library.luau globals. Preserve cmeta.rs C-origin string errors; avoid adding Lua source locations to security pcall results. Separate debug traceback presentation from error value.
5. Every thread creation must copy caller context: task spawn/defer/delay, legacy spawn/delay, coroutine create/wrap, scheduler threads, module execution and enabled loadstring. Audit all create_thread sites including testing_service.rs and services.rs. assets_cloud_scene::create_thread currently attributes memory from function environment; this is not security inheritance. Root script startup explicitly overrides inherited host context with game identity.
6. Capture security context at Connect/Once and restore it on freshly created delivery threads; runtime_signals::deliver currently retains only Functions. Wait resumes the existing waiting thread with its original authority. BindableEvent dispatch must not adopt firing thread authority. Apply the same model to engine signals, deferred delivery and cancellation. xpcall handlers/metamethods stay in executing thread context. Never infer identity from current script global or closure origin.
7. Require must run module with caller authority and segregate caches appropriately; test command/game ordering both ways and concurrent requires before choosing cache key. Any temporary context changes need RAII restoration through errors, yields and reentry; process-global identity switches are unsafe. Proposed loadstring inheritance requires enabled-mode Studio confirmation.
8. Regression acceptance should use the captured game-script probes, include asymmetric property policy, extracted method/event handles, cross-identity signals and callbacks, duplicate module requires, coroutine resumptions across identity boundaries and a renamed harness attempt. These last adversarial cases are recommendations, not measured results in this report.
